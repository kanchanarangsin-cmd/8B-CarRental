# HEURISTIC_RULES

**ระบบ:** ระบบเช่ารถยนต์ (Car Rental System)  
**รหัสกลุ่ม:** 8B  
**ที่มา:** UX Audit จากงาน HTS #1  
**หน้าจอที่เลือก:** Pain Point 2 หน้าการวิเคราะห์ และ Pain Point 3 หน้าการเช่า

## 1. การเลือกหน้าจอ

| Pain Point | หน้าจอ | เลือก / ไม่เลือก | เหตุผล |
|---|---|---|---|
| 1 | เพิ่มรายการเช่า | ไม่เลือก | ต้องเชื่อมรายการรถและลูกค้าจากฐานข้อมูลจริง รวมถึงตรวจรถว่างซ้ำ จึงมีความเสี่ยงกระทบโครงสร้างข้อมูลมากกว่างานรอบนี้ |
| 2 | การวิเคราะห์ | **เลือก** | ปัญหาตัวกรองหลายช่องแก้ได้ในระดับโครงสร้างข้อมูลและ Interaction โดยไม่เปลี่ยนฐานข้อมูล เหมาะกับการพิสูจน์ H7 ด้วย HTML ที่ทดสอบได้ทันที |
| 3 | การเช่า - คำสั่งของรายการ | **เลือก** | มี Severity 3 และกระทบความปลอดภัยของข้อมูลโดยตรง สามารถพิสูจน์ H5 ได้ชัดจากเมนูสามจุดและขั้นตอนยืนยันก่อนลบ |
| 4 | ตรวจคืนรถ | ไม่เลือก | ต้องเชื่อมสถานะรถ สถานะการเช่า และผลตรวจคืนหลายตาราง ขอบเขตการทดสอบมากกว่าสองหน้าที่เลือก |
| 5 | ยืนยันการบันทึกรายการเช่า | ไม่เลือก | เป็นสถานะย่อยของกระบวนการเพิ่มรายการเช่า และมีขอบเขตซ้ำกับ Pain Point 1 จึงเก็บไว้พัฒนาต่อใน HTS #2B |

## 2. ตารางแปลง Heuristic เป็น Design Rule

| ID | Heuristic ที่พบจาก HTS #1 | หน้าจอ | Rule ที่วัดได้ใน design.md | วิธีตรวจ |
|---|---|---|---|---|
| **R-01** | H7 Flexibility & Efficiency of Use - ผู้ใช้ต้องกรอกหลายเงื่อนไข | การวิเคราะห์ | ต้องมีรายการหัวข้อวิเคราะห์ให้เลือกอย่างชัดเจน และเลือก Active ได้ครั้งละ 1 หัวข้อเท่านั้น | กดหัวข้อทั้ง 5 รายการและตรวจว่า Active เหลือเพียงรายการเดียว |
| **R-02** | H7 Flexibility & Efficiency of Use - ตัวกรองไม่สัมพันธ์กับงานที่กำลังทำ | การวิเคราะห์ | หลังเลือกหัวข้อ ระบบต้องแสดงเฉพาะตัวกรองที่เกี่ยวข้อง 1 กลุ่ม พร้อม Label และคำอธิบาย ไม่แสดงช่องที่ไม่เกี่ยวข้อง | สลับหัวข้อ ลูกค้า / รายเดือน / สถานะ / ช่องทางชำระ / จำนวนครั้ง แล้วนับกลุ่มตัวกรองที่แสดง |
| **R-03** | H1 Visibility of System Status - ผู้ใช้ไม่เห็นผลของคำสั่งค้นหา | การวิเคราะห์ | ปุ่มค้นหาต้องมี Loading, ผลลัพธ์ต้องระบุจำนวนรายการ, การล้างค่าต้องแสดง Empty State และทุกผลลัพธ์ต้องมีข้อความภาษาไทย | กดค้นหาและล้างค่า ตรวจ Loading, Result Count, Empty State และ Toast |
| **R-04** | H5 Error Prevention - ปุ่มแก้ไขและลบอยู่ใกล้กัน | การเช่า | ในแต่ละแถวต้องมีปุ่มจุดสามจุดเพียงปุ่มเดียว เมนูต้องมี แก้ไข / ตรวจรถคืน / เส้นแบ่ง / ลบรายการ และห้ามมีปุ่มลบแสดงตรงบนแถว | ตรวจแต่ละแถวและเปิดเมนูคำสั่ง |
| **R-05** | H5 Error Prevention - ลบได้ทันทีโดยไม่มีการยืนยัน | การเช่า | การกดลบต้องเปิด Modal ที่ระบุรหัสการเช่า แจ้งว่าไม่สามารถย้อนกลับได้ มีปุ่มยกเลิก และปุ่มยืนยันสี Danger การลบจะเกิดขึ้นหลังยืนยันเท่านั้น | เปิดลบรายการ กดยกเลิก 1 ครั้ง แล้วเปิดใหม่และยืนยันลบ |

## 4. ขอบเขตที่ส่งต่อไป HTS #2B

- นำ R-01 ถึง R-05 ไปใช้เป็น Acceptance Criteria ของการแก้โค้ดจริง
- เชื่อม Search และ Filter กับฐานข้อมูลโดยไม่เปลี่ยนรูปแบบ Interaction
- เชื่อม Edit / Return Inspection / Delete กับ Route จริง โดยยังคง Confirmation Modal ตาม R-05
- ทดสอบสิทธิ์ผู้ใช้ก่อนอนุญาตให้ลบรายการจริง


## Section 7 — Final Iteration จากผลทดสอบ HTS 3

เพิ่มวันที่ 6 พฤศจิกายน 2569 สำหรับ F-01 และ F-02 ใน FORM 6 ตารางที่ 4
R-06 และ R-07 เป็นกฎใหม่จากผลทดสอบรอบนี้ ไม่ใช่กฎที่มีอยู่ตอน Audit HTS 1
คง R-01 ถึง R-05 และค่าของ token เดิมทุกค่า

| Rule | Finding | ผลที่ต้องเกิดบนหน้าจอ | วิธีตรวจ |
|---|---|---|---|
| R-06 | F-01 ผู้ทดสอบ 5/8 คนต้องรับคำใบ้ใน Task 1 | แผงลงทะเบียนมีปุ่มม่วงเข้ม “เพิ่มลูกค้าใหม่” พร้อมคำอธิบายสั้น ปุ่มเปิดฟอร์มเดิมและชื่อฟอร์มตรงกัน | เปิด customers.php ทั้งจอกว้างและจอแคบ กดปุ่มและตรวจหัวข้อฟอร์ม ช่องข้อมูล และการบันทึกจริง |
| R-07 | F-02 ผู้ทดสอบ 6/8 คนต้องรับคำใบ้ใน Task 2 | ราคาค่าเช่าต่อวันเป็นปุ่มข้อความขีดเส้นใต้พร้อมไอคอนดินสอ ชื่อปุ่มสำหรับโปรแกรมอ่านหน้าจอระบุราคาและรหัสรถ เปิดฟอร์มแยกที่มีเฉพาะช่องค่าเช่าต่อวันและให้โฟกัสช่องนั้น | เลือกรถสองคันสลับกัน ตรวจรหัสและข้อมูลตรงแถว ตรวจ focus แก้ราคาแล้วบันทึกและโหลดหน้าใหม่ ตรวจว่าข้อมูลอื่นและรถคันอื่นคงเดิม |

ใช้ color.nav กับปุ่มเพิ่มลูกค้า, color.primary กับตัวราคาที่กดได้ และ color.surface, color.badge.text, space-1 ถึง space-4 กับองค์ประกอบเดิม

เกณฑ์ตรวจเพิ่มเติมวันที่ 7 พฤศจิกายน 2569: R-06 ปุ่มเพิ่มลูกค้าใช้สีม่วงเข้ม ตัวอักษรขาว และยังอยู่ในแผงเดิม; R-07 ช่องค้นหาและตัวกรองอยู่เหนือตาราง และกดราคาของแต่ละแถวเพื่อเปิดฟอร์มที่ระบุรหัสรถตรงกับแถวที่เลือก
ฟอร์มลูกค้าปิดคำแนะนำการกรอกอัตโนมัติและซ่อนไอคอนรายชื่อของ Safari โดยช่องเบอร์โทรและเลขบัตรยังเก็บเป็นข้อความเพื่อรักษาเลข 0 ด้านหน้า CSS ใช้เฉพาะในหน้าลูกค้าและหน้ารถยนต์
กดตัวราคาเพื่อเปิดฟอร์มแยกที่มีเฉพาะช่องค่าเช่าต่อวัน พร้อมรหัสและทะเบียนรถสำหรับตรวจสอบ ปุ่ม “แก้ไข” ทางขวายังเปิดฟอร์มข้อมูลรถแบบเต็ม
ฟอร์มราคาใช้ POST แยกสำหรับอัปเดตเฉพาะ daily_rate ของรถคันที่เลือก ส่วนการบันทึกข้อมูลรถแบบเต็ม โครงสร้างฐานข้อมูล และวิธีคำนวณค่าเช่าคงเดิม
